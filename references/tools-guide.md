# 工具分工：什么软件适合做什么

**验证次数：低**——真正验证过的只有"封面裁切脚本"这一条；Codex 那行完全没测过，"写作用哪个工具更好"没有数据支撑。这份文档大部分是合理推测，不是确认过的结论，下次用到时先看是否还适用，不要在没有新证据前继续扩展它。

作者可能同时用 Claude、Codex、ChatGPT。原则：**一篇文章的文字、检查和文件只在一个工具里做**，避免两边各改一份、文件对不上；只有本工具做不了的环节（比如生图）才交给另一个工具。

下表是按这个项目的用法整理的，各工具的能力会变，以当时版本为准；标了“未验证”的是我没有在本项目里试过的。

| 环节 | 建议工具 | 为什么 | 状态 |
|---|---|---|---|
| 资料核实、写作、改稿、标题和封面提示词、审核 | Claude Code（本 skill 所在） | skill、画像、检查脚本和文章目录都在这里，能读写本地文件、联网读官方页、跑脚本 | 已在本项目里用 |
| 跑检查脚本、回归测试、批量改文件、写和改脚本 | Claude Code 或 Codex | 都是能读写文件、跑命令的编码代理；这类任务和写作无关，谁顺手用谁 | Codex 在本项目里的表现未验证 |
| 封面生图 | ChatGPT | 作者已有；把 review.md 里的“封面提示词”粘贴过去生成，下载后回到 Claude Code 裁切 | 生图效果和能否精确控制尺寸以当时版本为准 |
| 封面裁切、叠字、看 1:1 预览 | Claude Code 跑 `scripts/make_cover_card.py` | 图生成后要裁成 900×383，ChatGPT 通常不能精确指定像素尺寸 | 已在本项目里用 |
| 排版转换、发布、上传图片和封面 | 作者手动（Markdown 转公众号工具 + 公众号后台） | skill 不自动发布；粘贴后的最终效果要作者手机预览 | 粘贴到后台后的效果未验证 |

## 几点说明

- **Codex 能不能直接用 wxstyle**：wxstyle 是按 Claude Code 的 skill 格式写的（`SKILL.md` 加 `references/`、`scripts/`）。Codex 能否直接加载这种格式，我没有验证过。想在 Codex 里用，可以让它先读 `SKILL.md`，再按里面的链接读参考文档并运行脚本，跑完看看行为是否一致；不一致就以 Claude Code 里的结果为准。
- **不要两个工具同时改同一个文章目录**：一个工具改完并保存，再换另一个，改动后重新跑检查、重新记录哈希。
- **写作用哪个更好，没有数据**：我没有拿同一个选题在两个工具里对比过。想知道，就同一个选题、同样的资料，在两边各跑一次，对照“完成标准”清单和检查脚本的结果，不凭感觉判断。
- **生图是 ChatGPT 的事，但提示词由 skill 写**：提示词在 review.md 的“标题与封面”里，格式和模板见[标题与封面](title-and-cover.md)。生图工具画中文容易出错，所以提示词要求不放文字，文字用脚本叠。
- **图片版权和标注**：AI 生成的图在 delivery.json 里记为 `ai_generated`，保留提示词和生成工具；官方截图的授权由作者决定。
