# 图片作为文章材料

先看本次要求，再看己方visual_preferences的适用范围。素材类型与插画风格是两回事。

| 用途 | 优先素材 | 边界 |
|---|---|---|
| 产品身份 | 官网/发布页局部截图 | 保留名称、日期与来源；官方主张不等于独立结论 |
| 功能 | 实际界面/官方演示 | 区分官方示例、用户提供与作者实测 |
| 操作 | 真实输入、设置、输出截图 | 不生成UI冒充操作；未测试只能给资料路径 |
| 数据 | 原始图与条件，或忠实重绘并标来源 | 不截掉坐标/条件，不混同比较口径 |
| 社区讨论 | 有具体内容的原帖/评论局部截图 | 观点归作者，热度不等于真实性 |
| 解释结构 | 表格、列表或必要的示意图 | 与实测证据区分 |
| 封面/抽象概念 | 生图先从读者真实场景构图（见[标题与封面](title-and-cover.md)），其次插画或示意 | 不能替代产品证据；屏幕内容不画成产品真实界面 |

正文里需要给抽象概念配一张说明性插画（不是封面）、且当前会话能直接生图时可以生成，图注标明是示意图，保留完整提示词，delivery.json 里记为 ai_generated。封面的生图流程见[标题与封面](title-and-cover.md)。

## 获取和检查

1. 每张图写明“支撑哪段、增加什么信息”。重复装饰不算新增信息。
2. 用当前支持的浏览器截图能力在实际页面取图。保留原图，截相关范围，避免整页小字，去除无关隐私。不把重新排版的文字卡片伪装为原站截图。
3. 查看实际图片，确认文字可读、上下文未歪曲。记录URL、截图日期、来源类别和素材使用状态。公开访问不等于任意转载授权；不明素材不标商用许可，必要时用短引文和链接替代。
4. 图下注明看点与来源。英文可附明确标为意译的中文摘要；官方示例不标“我的测试”。
5. 不强制首图、结尾情绪图或每千字张数。长段用小标题、引用、表格停顿，删掉没有信息作用的图。

## 评论选择

读原帖和回复上下文。优先具体方法、测试条件、失败经验和有效疑问，不堆“太强了”。不硬凑一正一反，不以几条评论代表共识。核对平台、指标、数值和观察时间后才能称“热门/高赞”，否则称社区讨论。未经复核的性能数字只作个人自述。

优先能回答“他测了什么、怎么测的”的内容：贴了原题、交代了版本和条件、有具体输出或失败情况。正文写“某用户称”，不写“测试表明”；和官方说法冲突时两边都写。社区页面拦截抓取时不绕过验证，请作者粘贴原文并附链接、用户名、发帖时间；拿不到原文就不写这条评论。

## 获取失败

用户说工具不可用，也要在环境允许的范围内做一次有限恢复，再说明失败，不能一听说不可用就直接放弃。依次：①换一种受支持的取材方式（如读取页面文字确认名称、日期、数字原文；工具确实不可用就跳过并说明）；②请用户提供截图，或告诉用户截哪一段、截多大范围；③仍失败则保留来源网址、截图位置、失败原因。恢复的尝试和结果都写进 delivery.json 的 note 和最终回复。真实截图未取得不能用AI图替代后标完成。正文可先交付，delivery.json及最终回复保留缺图状态。
