# 找选题

验证次数：现行规则（1.13.0 起）真实用过1次，都没有阅读数据。攒够3篇有阅读数据的，再判断要不要扩展。

1. **粗筛**：按请求选渠道。新闻选题默认搜最近1—3天的资讯，凑不够3个就放宽到7天，每个候选写明发布日期；常青选题可从读者问题、机制讲解、比较分析、社区讨论或跨事件变化找角度，不受这个时间窗限制。按账号领域、读者问题和语言范围选来源，标题用于初筛，含义不清时读摘要或正文再决定。优先查与候选直接相关的一手材料，再补领域媒体或社区讨论；在回复里写明看了哪些来源、哪些没读到。例如 AI 产品选题可查官方更新日志、文档和博客（国内读者常用的 DeepSeek、豆包、Kimi、通义、元宝别漏，DeepSeek 的更新在 api-docs.deepseek.com 的更新日志），读书选题可查原书与作者访谈，本地生活选题可查当地公告和场所官方信息。找不到一手材料时，具名标注转述来源和核实缺口；泛搜只用来找线索。
   - **定位筛选**：把 positioning 写成读者价值问题，判断能否帮助读者行动、理解变化或作决定；“今天能直接用”适合工具教程，不作为所有文章的准入条件。例：写给不懂代码的人，就问“这件事会不会改变读者花的钱、用的时间或手里 AI 工具的用法？能不能用一句不带术语的话告诉他？”新闻本身偏开发者、但能换成读者角度的（如编程工具改订阅，换成“你的 AI 订阅怎么算钱”），收进来并标“需要换成读者角度”；公司内部动态、只有开发者碰得到的接口和跑分不收。只能通过 API 用的，除非值得写，否则不收；收了就标“需要换角度”。
   - 旧消息临近截止日（如几个月前的下线通知，数据几天后删除）可以进候选，但要标明“旧通知，新的是截止日”，写出截止日期，不当成新消息。
   - 去掉和 recent_topics、已有文章目录重复的。没有己方画像时，定位不明才问账号写给谁看；账号名已知时，按[画像规则](style-profile-schema.md)的“选题冷启动”创建并校验 bootstrap 画像。账号名未知时先完成选题，在回复里说明画像尚未保存，不猜账号名。
2. **标热度**（可选，验证次数：0）：可给已有候选查热度，也可发现新线索，可以跑 `hot_list.py` 看有没有上百度热搜。热搜可以提供新线索，但新增候选仍要过读者定位筛选和来源核实；不能仅凭关键词命中或排名入选。大众热搜里 AI 条目少，命中的多是 AI 只当背景的社会新闻或开发者向的消息，离定位远的说明原因后略过。读不到就写“热度数据没取到”。微博、知乎等要登录或验证的热榜不用，不绕过。
3. **细查3个**：粗筛留下的排前3个，读一手原文，再对照搜到的二手摘要和报道。其余的在回复末尾列标题和链接，一句带过。
4. **写信息差**：一手原文比二手摘要更准或更全的地方，写成一句并附原文链接，比如摘要漏了适用范围、给的数字找不到出处。找不到就写“无明显信息差”，不凑。只能和搜得到的报道比，比不了其他公众号，不写“别人都没写”。
5. **原文打不开**：标“原文没读到”，排到后面，不把转述当原文。
6. **交付**：每个候选写信息差、热度依据、读者看完能做什么决定、目标读者里大概多少人会受影响（说不清就写说不清和原因）、作者能不能补实测、核实难度，推荐一个。热度依据三选一：百度热搜排名、热度分和抓取时间；具名媒体列表（不写“N家报道”）；没有热度数据。上了热搜的候选提醒热度可能等不到发布。排序先看读者，再看信息差，热度只在前两项差不多时决定先后。不预测阅读量。作者选定后进入写作流程；发布后作者给了阅读数，记进 `performance_log`。
