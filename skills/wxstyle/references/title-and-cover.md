# 标题与封面：让人愿意点开

读者在信息流里是扫过去的。标题和封面合起来要在两三秒内回答一个问题：**这和我有什么关系，凭什么信你？** 两者分工，不重复：标题说“得到什么”，封面给“看一眼就记住的东西”。两者要指向同一个承诺，标题承诺什么，封面就用一个具体的画面或数字去呼应，不能各说各的。

标题写在 review.md，文章标题栏填的是它；正文不写标题。每次交付时，最终回复里要直接给出**推荐标题**；封面按 SKILL.md“输出”交付（没有图就做文字卡保底），提示词写在 review.md。

## 标题

### 先想一句话承诺

动笔前先用一句话写出“读者读完能得到什么”。写不出来，说明文章本身没想清楚，先回到正文。标题是这句话的压缩版。

### 三问，缺一个就重写

1. **对谁**：读者能不能一眼认出这是写给他的。“不懂代码，也该知道……”比“一个新模型”更清楚。
2. **得到什么**：读完能知道什么、能做什么决定，具体到事，不写“深度解析”“全面了解”。
3. **为什么可信**：有来源的数字、官方原话、作者亲眼看过的东西。没有依据的承诺不写。

### 几种写法（按证据选，不硬套）

| 写法 | 什么时候用 | 例子 |
|---|---|---|
| 判断式 | 作者有明确判断，且有依据 | Jev 快 40 倍？官方自测，还没人复现 |
| 场景式 | 读者能对号入座 | 工单该转给谁，AI 现在能先告诉你几成把握 |
| 反常识/短板 | 官方或资料里有真实的反差 | 官方自己列了一页 Jev 的短板 |
| 问题式 | 问题本身是读者真有的困惑 | 拿不准的事，AI 会不会说“我不确定”？ |
| 名词加限定 | 资料介绍、要被搜到 | Jev：一个会说“我有几成把握”的 AI |

### 生成步骤

1. 每种适用的写法各写一个，共 5—6 个，不要只改几个字。
2. 逐个过三问，淘汰过不了的。
3. 跑 `python scripts/claim_check.py --file article.md --title "标题"`，处理绝对化、热度词、标题党、无归因数字、超长。
4. 留 3—5 个，写清每个的写法、为什么会被点、风险；选一个推荐，并说明备选适合什么情况（比如“想被搜到用 3，想引发好奇用 2”）。
5. 避开 article_history 里近期用过的标题写法，别连着几篇同一个格式。

### 写的时候

- **含产品名或读者会搜的词**：公众号有搜一搜流量。
- **关键信息放前面**：手机列表里长标题会被截断，约 20 个字内说清主意更稳（经验，以你手机上的显示为准；`claim_check` 超过 30 字会提示）。
- **数字要带归因**：写“官方称快 40 倍”，不写光秃秃的“快 40 倍”。
- **不用相对时间**：“本周”“最近”“今天”过几天就错。
- **一个标题只讲一件事**。

### 不要写（也是 `claim_check` 会标的）

- **标题党**：震惊、必看、没想到、看完沉默。读者点进来发现对不上，下次就不点了，这个号的信誉是长期的。
- **绝对化和无依据的热度**：最强、颠覆、全网都在用。
- **暗示正文没有的东西**：标题承诺“三步上手”，正文却是资料介绍。
- **替作者编经历**：作者没实测，标题不写“我测了”“亲测”。

| | 例子 | 为什么 |
|---|---|---|
| 差： | 震惊！这个 AI 太强了，看完我沉默了 | 标题党，没有信息，读者不知道得到什么 |
| 差： | Jev 来了 | 不知道对谁、有什么用 |
| 好： | 拿不准就交给人：Jev 给每个判断附上“把握程度” | 对谁（要做判断的人）、得到什么（一个用法）、产品名在里面 |
| 好： | Jev 官方称快 40 到 200 倍，也自己写明了短板 | 有归因的数字，加一个可信的反差 |

## 封面：先表达内容，再选择风格

封面与标题一起评估。目标是让目标读者辨认主题、看到一个与正文有关的疑问或收益；没有真实发布数据，不能承诺点击率提高。

### 生成前的简报

在review.md用几句话记录：
- 推荐标题、目标读者、正文能兑现的一句话承诺。
- 产品识别线索：产品名、可辨认的真实界面或已有品牌素材；不必每张都放logo。
- 视觉要表达的关系：例如输入如何变成判断、确定与不确定如何分流。不能只写“科技感”“高级感”。
- 点击理由：读者看到什么具体反差、问题或结果会想了解；必须由正文支撑。
- 素材性质与文案：哪些是真实证据，哪些是编辑示意，封面文字逐字写出。
- 构图与裁切：宽幅封面与方形缩略图各保留什么。

先在内部比较两三个简短构想，选与正文最贴合的一个生成，不默认多出图或让用户先选。用户只要求一个明确方案时直接执行。

### 选画面，不强套隐喻

| 方向 | 适用条件 | 要避免 |
|---|---|---|
| 真实产品素材加编辑文案 | 官网或界面可辨认，能支撑核心卖点 | 整页英文小字、截掉限制、生成假官网 |
| 编辑示意加产品名 | 要解释分类、筛选、分流等关系 | 伪装成产品真实界面或真实输出 |
| 概念摄影或插画 | 物体与文章关系直接，缩略图也能读懂 | 只有漂亮静物，需要长篇解释隐喻 |
| 文字主导 | 画面无法清楚表达，但一句短文案有信息 | 无归因数字、夸大承诺、把全文塞进封面 |

用户说“真实感”时，结合语境区分真实来源与摄影质感；要求官网截图、评论原图时，摄影风生成图不能替代。既有visual_style_anchor只提供风格参考，不能压过主题关联。

一个视觉焦点可以包含少量有关联的元素，不等于只能画一个孤立物体。摄影、插画、文字与截图均可选，不统一规定暖色、无字或大留白。

产品名与短文案可以增强识别；与标题允许有必要的关键词重复，避免整句照搬。文字能可靠生成就直接生成并逐字核对；否则生成留字区底图，再用支持中文排版的工具叠字。现有make_cover_card.py适合短文字卡，不强迫复杂版式迁就它的字数限制。

不生成假评测数字、假评论、假界面。允许有来源的事实出现在封面，但来源限定必须可读；需要很多小字才能不误导的数字，移回正文。

### 生图提示词模板

```text
用途：公众号文章封面。
文章标题：[推荐标题]
读者与文章承诺：[谁读、能了解什么]
第一眼要读懂：[产品身份 + 一项具体能力或疑问]
画面关系：[哪些元素如何互动；不要只列一个物体]
素材性质：[真实素材的来源 / 明确的编辑示意或概念画面]
文字：[逐字列出产品名与短文案；或明确无字及识别替代方案]
视觉层级：[主焦点、辅助元素、文字大小与位置]
风格：[由主题和用户偏好选择；说明材质、光线或图形语言]
构图：[目标比例，宽幅及方形裁切分别保留的核心信息]
避免：[本方案特有的误读、假证据、拥挤小字和无关装饰]
```

优先用当前会话本身具备的生图能力；当前环境没有这种能力时，交付上面这份提示词给外部工具，目前是交给 ChatGPT，生成后回到 Claude Code 用 `make_cover_card.py --bg` 裁切——这是目前唯一真正验证过的路径，不固定要求用户换成别的应用。一篇文章的文字、检查和文件只在一个工具里改，别让两个工具同时改同一个文章目录。没有任何图时，按 SKILL.md“输出”的封面保底做文字卡。

### Jev案例：从文件托盘改为可辨认的判断过程

失败画面：米色背景、金属文件托盘、橙色纸片。它表达了办公收纳，却缺少Jev身份、输入输出关系与判断特点，容易被理解成收纳用品广告。提高材质真实度不能解决这个问题。

针对“Jev是什么？从客服分单看懂这个AI”的可用提示词：

```text
设计一张介绍Jev的公众号编辑封面，横版约2.35:1。
中央主视觉像一张清晰的编辑示意海报，上方大字“Jev”，下方短句“让AI先分单”。
主视觉呈现一张消息卡进入一个简洁的分流节点，分成两个清楚可见的出口：一个是整齐排列的工单卡，一个是等待人工查看的单独卡片。
消息卡只用短横线表示内容，不写虚构客户信息。用实线与虚线区分已分配与待确认，不使用概率、准确率或性能数字。
Jev与分流关系在中央方形裁切内仍能辨认，左右只做轻量延展，不用大面积空白把主体缩小。
深炭灰背景，白色清晰文字，一处醒目的橙色强调，图形有轻微纸张层次；风格是科技编辑设计，不是办公用品产品摄影。
这是解释分单思路的概念图，不是Jev真实软件界面。不画浏览器窗口、仪表盘、品牌logo、机器人或发光大脑。
```

此例是与正文对应的设计假设，不是已经验证能提高点击率的模板。其他文章要重新确定承诺和视觉关系，不能统一套分流图。

### 验收与保存

查看实际生成图后逐项判断，并把观察记录到review.md：
1. 联合标题看，能否辨认主题与文章承诺？陌生读者是否会误以为卖办公用品或讲另一个产品？
2. 画面是否表达了预定关系？只有物体、却没有动作或关系时，不能因“好看”直接通过。
3. 小尺寸下，产品名、核心文案和主视觉能否辨认？装饰是否抢走焦点？
4. 核对文字、数字、来源与示意身份，不能把概念图称为真实截图。
5. 检查宽幅和方形的实际预览；没有生成或看到裁切图就标未验证，不凭原图推测“裁切通过”。

头条封面可按900×383准备，方形预览用于检查转发场景，最终以后台裁剪框为准。安全区随实际尺寸与主体变化，不把320像素当所有画面的通用限制。裁切、叠字、缩放遵循当前图像工具的使用要求。

关联度失败先改概念，辨识度失败再改大小、对比和文字，局部错误才做定向修图。用户已否定的方案不要只换颜色再交付。有限修订后仍不合适，交代具体问题，不机械退回同样含混的文字卡。

保存原图、最终图、实际使用的完整提示词与已验证的预览。新版本另存，不覆盖旧素材。封面不记进delivery.json的assets（那里只记正文配图，记进去`check_delivery.py`会报错），生成工具、提示词和图片路径写在review.md的封面方案里。用户否定的旧封面标为不采用，不再称其为最终版。

## 数据回流

用户要求提高点击、比较方案或验证效果时，按[封面生成与测试](cover-testing.md)执行：先形成可测试假设，再区分设计预检、目标读者模拟和线上随机实验。普通封面不自动扩展成发布测试；未取得数据不宣称高点击。

用户提供发布数据时，记录曝光或推送口径、阅读/打开数据、标题封面组合和时间。设计审查只能判断相关性、可读性与误导风险，不能代替点击测试；不同文章的阅读差异不能直接归因于封面。
