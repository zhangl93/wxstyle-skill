# 成稿行为评测

eval_set.json仅验证触发。workflow_cases.json为独立的行为评测规格，不因文件存在就视为通过。

对每个案例，用最小资料和skill在独立临时目录执行请求；不提供预期答案给执行者，不发布、不付费、不进入真实账户。根据返回内容和产物逐项核对criteria，记录案例id、输入/产物位置、实际行为、pass/fail/blocked及原因。没有可用截图/账号时应评估失败降级行为，不伪造成功。

若未实际执行，结果记not_run。脚本单元测试只覆盖确定性行为，不能宣称验证文章质量或跨会话偏好使用。

请求里的 `{run}`、`{work}` 是占位符：`{run}` 换成本次运行的目录（放输入文件），`{work}` 换成当前项目目录（放已有文章目录）。N3、N4、N5、N6、B4、E1 需要事先准备输入文件（一篇待改的稿子、一篇成稿、几篇周刊原文、一个已有文章目录），其余用例不需要。

对比新旧版本时，把旧版 skill 复制一份，两版在相同的输入下各跑一次，逐条对照 criteria。单次运行样本小，差别只当参考。

**做“不用 skill”的对照时，要在提示里明确禁止调用 Skill 工具、禁止读任何 skill 目录**。本机全局装了 wxstyle 的话，子代理会自动加载它；只说“别读考试目录里那份”挡不住。2026-10-10 第一次做 `write` 盲评，对照组就这样用上了 skill（跑了检查脚本、读了真实画像），只能作废重跑。给考生的输入资料冻结成本地文件，并禁止联网，两组才可比。
